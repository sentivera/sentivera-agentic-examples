9.3 FHASL

Daily, a batch program is executed called the FHASL Interface that converts the financial transaction
activity posted to cases as of the run date into accounting entries at the case/transaction level with all
the necessary Fund, GL, and other codes. These transactions are created by completing a look-up on the
Crosswalk Table. The Crosswalk Table is a type of Pro-Forma or Standard Entry table that defines the
debits and credits and associated GL codes for each of the event/transaction codes. The existing
Crosswalk Table has been revised to add reversal transaction codes for all transaction codes.

=
Es cnaicco leat ceivable - Pascua nts,
[mm Sl a 10-1011-00 Sane: Fund Balance with Treasury - Collections

Figure 243: New Crosswalk Table

Each transaction either contains, or the interface executes a look-up on the corresponding Case Folder
to get the appropriate data element keys to the Crosswalk Table. The interface completes a look-up on
the Crosswalk using this key and adds the appropriate DR GL and CR GL Account Codes to each
transaction. All amounts are recorded as positive numbers in the file. Once a day, these transactions
are combined in a file that is delivered via FTP to HUD’s network each business day. The SMART FHASL
interface is loaded into a HUD Database at HQ and a second program is executed to summarize those
entries into Transaction Type/GL entries that are then posted in batch to the FHASL.

The Servicing Contractor completes a daily reconciliation of the FHASL Interface to the DAT A&B files
which is the SMART transaction activity to ensure all accounting events are translated into a valid GL
Account entry.

The tracking process includes a manual payment process that includes the following: When a payment is
received, the SMART Loan Notes are updated, the payment is deposited into the Servicing Contractor
Deposit account, the funds are collected, and when collected, a wire transfer or an ACH via PAY.GOV is
sent to the appropriate CFO HUD Program Office. Other than Notes, no Accounting Entries are made in
SMART and no accounting events are reported to FHASL. The recipient of the funds is responsible for
recording the accounting event in the appropriate financial systems. The loan is closed in SMART and the
Lien is released.
